# Revenue Agent — Feature Prioritization
### Smart Resort 360 | Hackathon Build Plan

---

## The Story We're Demoing
**Guest checks in → persona is known → demand signal arrives → price/offer adjusts in real time → dashboard shows why.**
A complete, working loop — not a dashboard, not a slide of ideas.

---

## Tier 1 — Must-Have Base Features (build first)

| # | Feature | Role in Demo |
|---|---|---|
| 1 | **Dynamic Pricing Engine** | Core mechanic — the agent's reason to exist |
| 2 | **Demand Forecasting** | Feeds the pricing engine a live signal to react to |
| 3 | **Real-Time Revenue Dashboard Feed** | Visual payoff for judges — RevPAR/ADR/occupancy, live |
| 4 | **Rate Authority Interface** | Proves multi-agent integration (Front Desk calls this for billing) |
| 5 | **Persona-Aware Offer Calibration** | Ties Revenue Agent to the Guest Type Labels spec — shows the two systems actually talk |

**Why these five:** together they form one coherent, demoable loop end-to-end. Everything else is a differentiator layered on top.

---

## Tier 2 — Unique Differentiators (pick 2, max 3)

| Feature | Why It Wins | Build Effort | Demo Moment |
|---|---|---|---|
| **Perishable Inventory Flash Sales** | High visual payoff; connects ops + guest experience + revenue in one flow | Medium | "Empty spa slot → push notification → booked live" |
| **Cost-Aware Rate Strategy (Net RevPAR)** | Strongest conceptual differentiator — optimizes *net profit*, not just top-line revenue | Medium–High | Toggle "close wing" → watch remaining room prices auto-adjust |
| **Predictive Cancellation & Smart Overbooking** | Credible, well-understood RM problem; shows ML competency without overreach | Medium | Show overbooking limit shift as a "high-risk" reservation is flagged |

**Recommendation:** Lead with Flash Sales + Net RevPAR. Add Smart Overbooking only if time allows.

---

## Tier 3 — Roadmap Only (mention, don't build)

Automated B2B/Group RFP Bidding · Hyper-Local Demand Sensing · Wallet-Share Tracking · Eco-Incentive Pricing · Gamified Demand Steering

> Strong ideas, but external API dependencies, ethics nuance, or thin data make them risky to build live. Present as "what's next" on a roadmap slide — shows vision without overcommitting build time.

---

## Pitch Framing
1. **Open** with the 5 base features as "the system that works" — the end-to-end loop.
2. **Differentiate** with 2 of the Tier 2 features — "what makes this different from a generic dynamic-pricing tool."
3. **Close** with Tier 3 as a roadmap slide — depth *and* vision, without overpromising.
